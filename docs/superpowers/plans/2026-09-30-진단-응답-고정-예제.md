# 진단 응답 고정 예제 Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** koshei 가 투영 함수로 지은 진단 요청 고정 예제 넷에 대해, 이 층의 진단 함수가 짓는 응답 넷을 저장소에 두고 코드와 어긋나지 않게 지킨다(진단 계약 0.6 §8). 그 앞에서 koshei 가 바꾼 `ref` 칸을 이 층이 읽게 하고, 칸이 빠진 요청을 거절한다.

**Architecture:** 요청은 koshei 정본의 바이트 사본이다 — 이 층은 투영을 다시 짓지 않는다. 응답은 손으로 쓰지 않고 `run_diagnosis` 에 사본을 넣어 짓는다. 시나리오마다 가짜 khala 답(`data` 봉투의 알맹이)을 파일로 고정하고, 시험이 시계를 고정해 시간 칸까지 결정적으로 만든다. 코드가 바뀌어 응답이 달라지면 시험이 빨개지고, 의도한 변화면 `NARRATOR_UPDATE_FIXTURES=1` 로 다시 짓는다 — 그 판은 일부러 빨갛고 환경 변수 없이 다시 돌려야 초록이다(koshei 쪽 `-Dkoshei.updateFixtures=true` 와 같다).

**Tech Stack:** Python 3.13, pytest. 새 의존 없음.

**기준 시험 수:** 시작 280(`temporalio` 가 있을 때). 기존 시험 둘을 늘리고(수 무변) 새 시험 함수 둘 × 예제 넷 = 8 을 더해 **288** 이 된다. `temporalio` 가 없으면 283 passed, 1 skipped.

**선행 조건:** koshei 가 `CHOOSE_SOURCE` 의 `ref` 를 `{jobOrderId, material, missingSource, alternative, searchId}` 로 고친 새 요청 03 을 커밋해야 한다(koshei 가 알린다). 옛 03(`ref.source`)은 Task 1 의 새 읽기 규칙에 걸려 거절된다.

**쓰는 규약:** 문서와 주석은 평서체. 줄끝 LF, UTF-8, BOM 없음. 커밋은 제어 세션이 한다 — 작업자는 `git add` · `git commit` 을 하지 않는다. 이 계획서의 산문에서 「」는 찾거나 넣을 글자를 감싼 인용 부호다 — 코드 블록 밖의 「」를 파일에 옮기지 않는다. **추적 파일에 개인 경로(사용자 홈 아래의 절대 경로) · 토큰 값을 쓰지 않는다** — koshei 작업 트리의 실제 자리는 작업을 맡길 때 따로 준다.
