# 머리 줄의 제목 꾸밈 Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 첫 실물 진단에서 모델이 표지 줄을 Markdown 제목으로 꾸며 권고가 버려진 것을 막는다 — 자료 칸의 답하는 법에 꾸밈 금지를 적고, 파서가 줄머리의 제목 기호(`#`)를 목록 기호 · 굵게처럼 꾸밈으로 받게 한다.

**Architecture:** 두 겹이다. 뿌리는 지시다 — 답하는 법(`diagnose/context.py` 의 `HOW`)이 「두 줄은 제목 · 목록 기호 · 굵게 없이 줄머리에, 값은 같은 줄에」를 말한다. 그래도 꾸미면 파서(`diagnose/answer.py` 의 `_HEAD`)가 `#` 를 벗기고 읽는다. 제목 아래 다음 문단으로 쓴 이유는 「이유:」 줄이 아니므로 읽지 않는다 — 이유를 안 댄 것으로 쳐서 자동 승인에서 빠지는 안전한 쪽이다. 다섯 표지(카드)는 설명 경로의 카드 파서 그대로 두고 넓히지 않는다 — 설명 측정의 카드 완결 수가 같은 파서를 쓴다.

**Tech Stack:** Python 3.13, pytest. 새 의존 없음.

**기준 시험 수:** 실행 시점의 수 그대로다(지금 280, 응답 고정 예제 계획이 먼저 들면 288). 기존 시험 둘을 늘리기만 한다.

**쓰는 규약:** 문서와 주석은 평서체. 줄끝 LF. 커밋은 제어 세션이 한다 — 작업자는 `git add` · `git commit` 을 하지 않는다. 산문의 「」는 찾거나 넣을 글자를 감싼 인용 부호다.

⛔ **까닭 — 첫 실물 진단 한 번 (2026-09-30).** khala 가 `answer_context` 를 받은 뒤(khala `8a501d2`) koshei 요청 예제 01 하나를 진단 함수로 실물에 보냈다(측정 판이 아니라 배선 확인). 257초, 자료 칸 285자가 다 쓰였고 인용 16 이 모두 검증됐다. 모델은 절차서의 기대대로 `ESCALATE` 를 권했는데 **표지 줄을 「## 권고: ESCALATE」로, 이유를 「## 이유」 제목 아래 다음 문단으로 썼다.** 파서는 목록 기호와 굵게만 벗겨 표지를 못 읽었다 — 결과는 후보 밖(`picked` null), 이유는 null. 둘 다 사람에게 가는 안전한 쪽이지만 권고 측정의 수가 크게 휜다. 추정 원인은 khala 시스템 프롬프트가 `##` 절로 짜여 있고 답변 형식 규칙에 「설계-관측 차이가 있으면 별도 섹션」이 있는 것이다(khala 에 알렸다). **측정 판을 돌리기 전에 고친다** — 잰 수를 거슬러 바꾸지 않는다.
